================================================================================
                    NEOVIM LUA & LAZY.NVIM MIGRATION PLAN
================================================================================

Target: Migrate existing Vim setup (~/.vimrc, ~/.vimrc.bundles, ftplugins) 
        to a modern Neovim (v0.10+) Lua configuration with zero-downtime fallback.

--------------------------------------------------------------------------------
1. AGREED ARCHITECTURAL DECISIONS
--------------------------------------------------------------------------------

- Configuration Architecture: Clean modular `lazy.nvim` setup
  (1:1 port of existing muscle memory, keybindings, and options into idiomatic Lua).
- Fuzzy Finder: `ibhagwan/fzf-lua` + `ripgrep` + `fd`
  (Preserves existing `<C-p>` and `\` grep workflow with native Neovim speed).
- Day-1 Language Tooling:
  1. C# / .NET: Mason OmniSharp / Roslyn LSP, CSharpier formatting, netcoredbg DAP.
  2. TypeScript / JavaScript / React: ts_ls / vtsls, ESLint, Prettier via conform.nvim.
- Theme: `ellisonleao/gruvbox.nvim` (dark mode matching current palette).
- Status & UI: `nvim-lualine/lualine.nvim` + `akinsho/bufferline.nvim` + `which-key.nvim`.
- Fallback Strategy: Side-by-side coexistence (`vim` vs `nvim`) with zero risk to `~/.vimrc`.

--------------------------------------------------------------------------------
2. ZERO-RISK COEXISTENCE & FALLBACK STRATEGY
--------------------------------------------------------------------------------

A. Storage Isolation:
   - Classic Vim strictly reads: `~/.vimrc`, `~/.vimrc.bundles`, and `~/.vim/`
   - Neovim strictly reads: `~/.config/nvim/init.lua` and `~/.local/share/nvim/`
   - Existing `.vimrc` files will remain completely untouched.

B. Instant Fallback Modes:
   - Run `vim <file>`  -> Launches classic Vim with existing `~/.vimrc`.
   - Run `nvim <file>` -> Launches new Lua Neovim config.
   - Run `nvim -u ~/.vimrc <file>` -> Boots Neovim with old vimrc if needed.

--------------------------------------------------------------------------------
5. STEP-BY-STEP IMPLEMENTATION ROADMAP
--------------------------------------------------------------------------------

STEP 1: Directory & Bootstrap Setup
  - Create `config/nvim` in dotfiles repo (and link to `~/.config/nvim`).
  - Write `init.lua`, `lua/config/lazy.lua`, `lua/config/options.lua`, 
    `lua/config/keymaps.lua`, `lua/config/autocmds.lua`.

STEP 2: Theme & Fuzzy Finding
  - Configure `gruvbox.nvim` with matching colors.
  - Setup `fzf-lua` with `<C-p>` (files) and `\` (ripgrep project search).

STEP 3: Treesitter & UI
  - Setup `nvim-treesitter` for AST-based highlighting.
  - Setup `lualine.nvim` statusline and `bufferline.nvim` buffer tabs.
  - Setup `gitsigns.nvim` for gutter diffs and hunk actions.

STEP 4: LSP, Completion & Formatting (TS + C#)
  - Configure `mason.nvim` and `nvim-lspconfig` for `ts_ls` and `omnisharp`.
  - Configure `conform.nvim` for Prettier and CSharpier on save.
  - Configure `nvim-cmp` or `blink.cmp` for autocomplete.

STEP 5: C# Development & DAP
  - Wire C# specific LSP commands (`gd`, `gr`, `K`, `<Leader>ca`, `<Leader>rn`).
  - Wire `nvim-dap` for .NET debugging with `netcoredbg`.

STEP 6: Validation & Verification
  - Launch `nvim`, verify zero startup errors and fast boot (<50ms).
  - Verify C# and TypeScript projects with autocomplete, definitions, and formatting.
  - Test instant fallback using `vim` and `nvim -u ~/.vimrc`.
